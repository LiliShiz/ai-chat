# Requirements — v1

Источник: `TASK.md` (ТЗ работодателя). Каждое требование ТЗ отражено здесь
с REQ-ID и привязано к фазе в `ROADMAP.md`.

## v1 Requirements

### Прокси и ключ (PROXY)

- [ ] **PROXY-01**: Сервер принимает `POST /api/chat` с историей сообщений и
      проксирует запрос в OpenRouter, подставляя ключ из серверного окружения
- [ ] **PROXY-02**: Ключ OpenRouter отсутствует в бандле фронта и в любом
      запросе со страницы — проверяется вкладкой Network
- [ ] **PROXY-03**: Ответ OpenRouter ретранслируется как SSE-поток без
      буферизации на сервере
- [ ] **PROXY-04**: Разрыв клиентского соединения прекращает запрос
      к OpenRouter (проброс отмены на апстрим)
- [ ] **PROXY-05**: Ошибки апстрима (429, 5xx, таймаут) нормализуются в единый
      машиночитаемый формат ошибки для фронта

### Диалог (CHAT)

- [ ] **CHAT-01**: Пользователь отправляет сообщение и получает ответ модели
- [ ] **CHAT-02**: Текст ответа появляется по мере генерации, а не одним куском
- [ ] **CHAT-03**: Пока идёт генерация, виден индикатор «модель печатает»
- [ ] **CHAT-04**: Кнопка «Стоп» обрывает генерацию; полученный до обрыва кусок
      остаётся в истории, интерфейс остаётся рабочим
- [ ] **CHAT-05**: История диалога сохраняется в рамках сессии и переживает
      перезагрузку страницы (`sessionStorage`); решение обосновано в README
- [ ] **CHAT-06**: Историю можно очистить

### Ошибки и края (ERR)

- [ ] **ERR-01**: 429 от бесплатной модели показывается как понятное состояние
      («лимит бесплатной модели, попробуйте через N секунд»), а не спиннер
- [ ] **ERR-02**: Таймаут ответа завершается явным состоянием с возможностью
      повтора
- [ ] **ERR-03**: Обрыв сети во время стрима сохраняет частичный текст и
      показывает, что связь прервалась
- [ ] **ERR-04**: Любая ошибка оставляет интерфейс живым: поле ввода доступно,
      есть кнопка «Повторить»

### Доступность (A11Y)

- [ ] **A11Y-01**: Весь интерфейс проходится с клавиатуры: Tab по элементам
      в логичном порядке
- [ ] **A11Y-02**: Enter отправляет сообщение, Shift+Enter — перенос строки
- [ ] **A11Y-03**: Esc останавливает генерацию
- [ ] **A11Y-04**: Разметка семантичная: `main`, `form`, `ul/li` для ленты,
      `button`, `label`, роли и `aria-live` для потоковых обновлений
- [ ] **A11Y-05**: Дефолтный браузерный `outline` снят, но фокус остаётся
      визуально различимым через кастомный `:focus-visible` — пушбек к ТЗ
      задокументирован в README

### Интерфейс (UI)

- [ ] **UI-01**: Адаптивность: на телефоне ничего не уезжает, ввод не
      перекрывается клавиатурой
- [ ] **UI-02**: Пустое состояние до первого сообщения: что это, что можно
      спросить, какая модель
- [ ] **UI-03**: Тёмная тема (бонус) — следует системной `prefers-color-scheme`
- [ ] **UI-04**: Рендер markdown в ответах модели (бонус)

### Процесс и сдача (PROC)

- [ ] **PROC-01**: Работа в feature-ветках, осмысленные атомарные коммиты
- [ ] **PROC-02**: Минимум один Pull Request с человеческим описанием, слитый
      в `main`
- [ ] **PROC-03**: README: запуск локально за 5 минут, ключевые решения и
      почему именно так, что сделал бы за ещё один день
- [ ] **PROC-04**: ИИ-лог в README: инструменты, где ИИ ошибся, как поймали
- [ ] **PROC-05**: Файл LICENSE (MIT)
- [ ] **PROC-06**: Публичный репозиторий на GitHub

## Out of Scope

- Аутентификация — ТЗ не просит, чат одноместный
- Docker/CI/CD/деплой — сдача идёт исходниками
- E2E-тесты Playwright — не влезает в бюджет 2–6 часов, честно отмечается
  в README как «что дальше»
