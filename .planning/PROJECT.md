# AI Chat — тестовое задание (фронтенд + ИИ)

## What This Is

Одностраничный веб-чат с языковой моделью через OpenRouter: пользователь пишет
сообщение — модель отвечает потоком. Это тестовое задание на вакансию
фронтенд-разработчика (React/Vue + работа с ИИ). Полное ТЗ — в `TASK.md` в корне
репозитория.

Оценивается не только результат, но и путь: коммиты, PR, README, ИИ-лог и
суждение — что кандидат заметил в задании и как обосновал отклонения.

## Core Value

Диалог с моделью должен работать надёжно на краях: стриминг идёт, «Стоп»
обрывает без потери уже полученного текста, а 429 / таймаут / обрыв сети дают
понятное состояние вместо вечного спиннера. Всё остальное — вкус поверх этого.

## Requirements

### Validated

### Active

- [ ] Диалог с моделью через OpenRouter (бесплатная модель с суффиксом `:free`)
- [ ] Потоковый вывод ответа по мере генерации
- [ ] Кнопка «Стоп»: обрыв генерации, частичный ответ остаётся в истории
- [ ] Явные состояния ошибок: 429, таймаут, обрыв сети
- [ ] История диалога в рамках сессии + осознанное решение про перезагрузку
- [ ] Ключ OpenRouter никогда не попадает в браузер (серверный прокси)
- [ ] Клавиатурная доступность: Tab, Enter — отправка, Esc — стоп
- [ ] Семантичная разметка, адаптив, индикатор «печатает», пустое состояние
- [ ] README: запуск за 5 минут, решения, ИИ-лог, что дальше
- [ ] LICENSE (MIT), ветки, осмысленные коммиты, хотя бы один смерженный PR

### Out of Scope

- Аутентификация пользователей — ТЗ не просит, чат анонимный и одноместный
- Серверное хранение истории / БД — «история в рамках сессии» по ТЗ
- Выбор модели из UI-каталога — одна `:free` модель достаточна, каталог это
  отдельная фича с пагинацией и фильтрами
- Мультичаты / ветки диалогов — за пределами «одностраничного чата»
- Тяжёлый CI/CD, Docker, деплой — сдача идёт исходниками в публичном репо
- E2E-тесты на Playwright — при бюджете 2–6 часов дороже, чем дают; в README
  честно указывается как «что сделал бы за ещё один день»

## Context

- **Оценочные приоритеты работодателя** (в их порядке): работоспособность и
  края → инженерные решения (где ключ, как стриминг и отмена) → процесс →
  суждение → вкус в интерфейсе.
- **Заложенная ловушка.** ТЗ одновременно требует «полноценно пользоваться
  с клавиатуры» и «убрать стандартную обводку фокуса (`outline`) у кнопок и
  поля ввода». Буквальное исполнение второго ломает первое: клавиатурный
  пользователь теряет позицию фокуса (WCAG 2.4.7 Focus Visible, уровень AA).
  Правило игры прямо поощряет такой пушбек. См. решение ниже.
- **Вторая развилка, отданная кандидату явно**: переживает ли история
  перезагрузку страницы. Ответ важен не сам по себе, а обоснованием.
- OpenRouter отдаёт стрим в формате OpenAI SSE (`data: {...}` + `data: [DONE]`),
  бесплатные модели жёстко лимитированы по RPM/RPD — 429 ловится легко и его
  реально можно продемонстрировать.

## Constraints

- **Tech stack**: React 19 + TypeScript + Vite на фронте, Node + Hono на бэке.
  Причина — вакансия про React/Vue, Hono даёт нативный Web Streams и
  разворачивается и в Node, и в serverless одной строкой.
- **Security**: ключ OpenRouter живёт только в серверном `.env`; браузер ходит
  исключительно на собственный `/api/chat`. Проверяется вкладкой Network.
- **Timeline**: 2–6 часов чистого времени. Что не влезло — описывается словами.
- **Dependencies**: зависимостей минимум. Markdown — только если останется
  время (бонус, не требование).
- **Process**: работа в feature-ветках, атомарные коммиты, минимум один PR
  с человеческим описанием, слитый как в обычной командной работе.

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Убрать дефолтный `outline`, но дать свой видимый `:focus-visible` | Буква требования выполнена (браузерной разнобойной обводки нет), дух доступности сохранён. Полное удаление фокуса нарушает WCAG 2.4.7 и противоречит соседнему требованию того же ТЗ. Пушбек описывается в README | — Pending |
| `sessionStorage` для истории | Переживает F5 и случайное закрытие вкладки по горячей клавише, но не утекает в другие вкладки и умирает вместе с сессией. Для чата с LLM, где в переписке бывают личные данные, `localStorage` — лишний след на чужой машине | — Pending |
| Прокси на Hono, а не на Express | Нативные Web Streams (`ReadableStream`) вместо ручного pipe; тот же код едет в serverless без переписывания | — Pending |
| Ретрансляция SSE, а не буферизация на сервере | Прокси не должен добавлять свою задержку — иначе «потоковый вывод» превращается в фикцию на стороне сервера | — Pending |
| `AbortController` сквозь весь стек (UI → fetch → прокси → OpenRouter) | «Стоп» должен реально прекращать генерацию и переставать жечь квоту, а не просто прятать текст в UI | — Pending |
| GSD-артефакты (`.planning/`) коммитятся в публичный репо | ТЗ прямо просит показать процесс и честный ИИ-лог. Планы в репо — доказательство метода, а не декларация в README | — Pending |
| Research-фаза GSD пропущена | Домен известен, ТЗ само является спецификацией. Четыре ресёрч-агента по экосистеме чатов — трата бюджета без влияния на результат | — Pending |
